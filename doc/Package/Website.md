# Project website (GitHub Pages)

The site is the interactive Vue/Vite playground in `test/app`, not the npm package build. It contains a main playground (`#example`) and a manual console callsite verification page (`#devtools`).

- Workflow: `.github/workflows/pages.yml`
- **Current trigger:** pushes to `master`, plus manual dispatch.
- Pages artifact: `dist/`, generated by `pnpm build:pages`.
- Site base URL: `/js-log-lens/` in Vite `ph-pages` mode.
- Intended site: https://oploshka.github.io/js-log-lens/

The local development server uses `pnpm serve` (Vite HMR, `base: '/'`). `pnpm build:demo` builds with the local base; `pnpm build:pages` uses `--mode ph-pages` and the project subpath.

Vite is configured with `root: test/app`, so the HTML entry is `test/app/index.html`. Hash navigation does not require a GitHub Pages SPA fallback or a separate history-mode router.

## GitHub repository settings

In **Settings → Pages**, select **GitHub Actions** as the build and deployment source. The workflow configures Pages, uploads the generated `dist/` artifact and invokes `actions/deploy-pages`.

The `github-pages` environment may restrict deployment branches. The `github-pages` environment should allow deployments from `master`. A rejected deployment with a message about environment protection rules is a **repository setting**, not a Vite build failure.

**Deployment policy:** active development happens on `develop`; GitHub Pages is published from `master` after updates have been promoted. A manual workflow dispatch should likewise select `master`.

GitHub Pages hosting and npm publication are independent.
